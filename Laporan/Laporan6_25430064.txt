## 1. Tujuan Praktikum
1. Mampu mengimplementasikan manipulasi data (DML) seperti `INSERT`, `UPDATE`, dan `DELETE` pada basis data MariaDB/MySQL.
2. Mampu mengeksekusi skrip DDL dan DML menggunakan perintah `SOURCE` melalui CLI MariaDB secara batch.
3. Mampu melakukan uji integritas data serta menguji batasan pengaman Safe Update Mode (`sql_safe_updates`).
4. Memverifikasi keberhasilan pemuatan data master dan transaksi menggunakan fungsi agregasi seperti `COUNT(*)`.

## 2. Ringkasan Dasar Teori
Data Manipulation Language (DML) adalah sekumpulan perintah SQL yang digunakan untuk mengelola dan memanipulasi data di dalam tabel basis data. Perintah `SOURCE` memungkinkan eksekusi berkas skrip SQL eksternal secara langsung dari CLI. Selain itu, fitur keamanan *Safe Update Mode* (`sql_safe_updates`) berfungsi untuk melindungi integritas data dengan mencegah eksekusi perintah `UPDATE` atau `DELETE` massal tanpa menyertakan klausul `WHERE` yang menggunakan kolom kunci (*Primary Key* atau *Indexed Key*).

## 3. Hasil Langkah Percobaan

- Memuat data master dan data sampel transaksi melalui berkas skrip DML `p06_data_064.sql`.
- Melakukan verifikasi jumlah data transaksi pesanan menggunakan fungsi `SELECT COUNT(*) FROM pesanan;`.
- Menguji mekanisme perlindungan *Safe Update Mode* yang memicu galat saat pembaruan data tanpa klausul `WHERE` yang spesifik.

## 4. Jawaban Titik Analisis
1. **Titik Analisis 1:** Kegagalan eksekusi perintah `SOURCE` dengan `error: 13` atau `error: 2` umumnya disebabkan oleh path direktori yang mengandung spasi atau salah pengetikan nama berkas. Solusinya adalah memastikan berkas berada pada folder tanpa spasi (seperti `D:\basisdata_25430064\`) dan memanggil path secara akurat.
2. **Titik Analisis 2:** Pesan `ERROR 1175` muncul karena fitur *Safe Update Mode* aktif untuk mencegah modifikasi atau penghapusan data secara tidak sengaja pada seluruh baris tabel akibat tidak adanya filter `WHERE` pada kolom kunci.
